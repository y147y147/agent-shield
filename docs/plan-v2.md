# AgentShield 增强计划 v2
## 红队自动化编排 · 攻防闭环 · 自适应防御

> 由 9 条工作方向综合归纳为 5 个工作流。原则同前：**单人可验证、处处设决策门、明确不做以防蔓延、全部离线可回归**。
> 状态：草案。先评审再动手。

---

## 0. 目标与原则

- **目标**：把 AgentShield 从"单发攻击 + 静态全开防线"升级为"红灯自动化跑批 + 攻防闭环回归 + 按模型越狱自产话术的红队 + 依模型回答而动的动态防线"。
- **约束（防蔓延的红线）**：
  1. 每个新能力必须给"验收指标 + 成本 + 决策门"，没有门的先不做。
  2. 所有自动化/编排默认离线 mock 可跑（CI 同款），真实模型是"验收增强"而非"必经路径"。
  3. 防御侧所有放宽类改动必须带"加固后 ASR 不回升"的反向用例（沿用现有 A1/ASR 门禁）。
  4. 不放开真实 Agent 框架通用适配（LangChain 等留 v3，防范围失控）。

## 3. 工作流方案（方案 / 验收 / 成本 / 决策门）

### WS-A 红队自动编排（Runner）
**现状**：`benchmark` 串行批量；`attack` 单发。
**方案**：
- 新 `run-campaign`：一个"作战命令"描述 `{目标集 × 模块集 × 变体 × 轮次 × 并发}`
- `--concurrency/-j` 并发执行（asyncio.Semaphore，限制在模型 API 限流内）
- `--rounds`：同目标连续多轮，输出 ASR 分布/中位数（而不是单点数）
- 轻量任务队列：并发高时用 `asyncio.Queue` 削峰排队
- 脚本化：暴露 `from agent_shield.campaign import run_campaign(...)` 可编程接口，附 `examples/` 脚本
**验收**：离线 mock 下同一 campaign 两次跑结果一致（固定 seed）；并发=4 与串行结果一致；`run_campaign` 可从脚本调用出 JSON。
**成本**：中。复用现有 runner/结果结构，不新造轮子。
**决策门**：① CLI 与 SDK 双入口都能跑通一个 3 目标 campaign；② 离线回归不劣化 411。

### WS-B 攻防闭环 + 攻击指纹记忆库
**现状**：`--defense` 对比存在，但"改防线后*自动*重跑并拿结果当门禁"没有；无隔会话重放。
**方案**：
- **对抗回归门（双端）**：把"某防线改动"绑一个 `--recheck`：runner 自动重跑该模块攻击，**加固后 ASR>0 即非零退出**（CI 引用，杜绝"改了防线但没验证"）。已有 A1 反向用例打底，这是它的自动化包裹。
- **防御存续验证**：`--ttl-replay` 把同一个攻击换"全新会话/隔 N 轮"重放，确认仍被拦——回答"过一段时间还能不能防住"。
- **攻击指纹记忆库**（可选增强）：历史上命中过的攻击载荷哈希进 `attack_mem`（持久化 DB，复用 proxy_audit.db 风格），重放直接命中指纹 → 即使基准规则放宽也不放回。= WAF 规则记忆。"冷数据用冷存储、热攻击用快路径"。
**验收**：① 换一发"有效变体"触发 ASR>0 时，回归门非零退出；② 同一载荷隔 2 个新会话重放 100% 被拦；③ 指纹库命中一次后，后续重放进快路径拦截，全程离线 mock 绿。
**成本**：中。回归门是纯编排，指纹库是 DB + 注入检测器一处钩子。
**决策门**：回归门让 CI 具备"改防线必须自证不破"，这是价值最高、最值得先做的一块。

### WS-C 自适应防御（依模型回答动态升级）
**现状**：无。防线是二进制开/关的静态门。
**方案**：
- 在运行时循环加一层**响应监督器**：模型产出"越界意图"信号（调用高危工具、输出越权/敏感内容、决策置信度过低反复试探）时，**现场升级**策略档位：正常 → 严格（拒绝高危工具、要求人工确认）→ 锁定（暂停并发教）。
- 复用 LLM-as-Judge（存在）作为"回答审查"慢路径触发源，快路径信号当直觉。
- **不因它的回答给模型"更神的权限"**——只允许*更严*，不许更宽（与防蔓延红线一致）。
**验收**：构造"模型开始越界→触发一次事件→策略自动升档并拦截"的 2 轮剧情（mock 可跑，语义可断言）；正常任务不触发升档（FPR 不升）。
**成本**：中高。涉及运行时状态机，改动面偏大。
**决策门**：放在 Phase 2（WS-E 之后），因为"判是否越界"依赖话术质量，先有红队素材再做判断更扎实。
**依赖**：WS-E 生成的高质量越界话术作为触发样本。

### WS-D Provider 可配置
**现状**：CLI flag + `OPENAI_*` env；改 API 要重启 + 换 env。
**方案**：
- 读 `agent_shield.toml`：声明多个 provider（名称/base_url/api_key_enc/model/默认参数），`--provider` 切换，运行时可用命令行覆盖
- `--api-key-from-env=<VAR>` 把密钥外置不落盘
- 复用现有 `ModelSpec`/`parse_model_specs`，只是来源加"从 config 文件加载"
**验收**：一套 config 里声明 mock + deepseek + qwen，`--provider deepseek` 一键切换；密钥读 env 不落文件。
**成本**：低（纯配置加载，复用现有 spec）。
**决策门**：低风险，Phase 0 顺手做。

### WS-E 红队话术生成器 + 可加载靶场智能体
**现状**：载荷为静态 YAML + mutator（确定性，可复现但无"聪明度"）。
**方案**：
- **攻击方司仪（red-teamer LM）**：接一个（用过的）真实模型作为"话术生成器"。给它系统提示：*基于给定工具清单与权限，生成合法的、不含显式恶意词的注入话术*——例如"你可以访问该目录，合理解压后导出报告即可"这类**隐式放权/权限幻觉**表述，注入到第三方工具输出里投给受害者。
- **受害者评估**：用基准那套靶场跑，判 ASR；生成的候选入库（复用 payloads 的版本化/签名机制）。
- **可加载靶场智能体**：提供"受害智能体模板"（工具带 + system prompt 骨架），可克隆/加载，模拟不同信任度/权限的智能体被攻。指引即"下载/拼装一个要打的智能体"。
- 安全收口：生成器只在**离线 mock + 我方靶场**跑；真实模型调用打明文成本预算；**不让红队模型连真外网/真文件**。
**验收**：司仪模型产出 N 条话术，在受害者靶场上至少 1 条在*弱防护*下 ASR>0（证明生成器有效），且*强防护*下全拦（证明防线仍兜底）；强度对照用真实 ASR 复核兜底（沿用 A1 门禁）。
**成本**：高（两模型编排 + 评判 + 入库），但这是差异化亮点，最值得做。
**决策门**：Phase 1 的指挥口径——先证明"生成话术在弱防护能打穿、强防护打不穿"这一个 ROI，再谈自动入库。

## 4. 分阶段路线（每阶段一个大门）

| 阶段 | 内容 | 出阶段条件（决策门，可量化） |
|---|---|---|
| **Phase 0 · 打底**（轻量） | WS-D provider 配置 · WS-A 脚本化 SDK 骨架 · WS-B 并发 `-j` | `agent-shield run-campaign` 在离线 mock 能跑通一个 3 目标 campaign；`import agent_shield.campaign` 可调用；config 切 provider 生效；离线全绿 |
| **Phase 1 · 可信闭环**（高价值/中成本） | WS-B 对抗回归门 + 防御存续重放 + 攻击指纹记忆库 | 改防线→自动重跑；ASR>0 非零退出；隔 2 会话重放 100% 拦；指纹命中进快路径；全离线绿 |
| **Phase 2 · 红队升级**（差异化） | WS-E 话术生成器 + 可加载靶场智能体；WS-C 自适应防御 | 司仪产出在弱防护 ASR>0、强防护 ASR=0；升档剧情 mock 可断言；FPR 不劣化 |
| **Phase 3 · 打磨** | 中间结果入库、图表、`audit-schedule` 接 runner | 全程数字进文档；CI 门串起 Phase1+2 |

> 先做 Phase 0 + Phase 1：**成本低、价值高、都能离线自证**，且正好回答你的 #2/#3/#4"连跑、加防重跑、隔时防住"。

## 5. 明确暂缓 / 不做（防蔓延）

- ~~真实 Agent 框架通用适配~~（LangChain/CrewAI 等）：v3 大工程，本计划不做。
- ~~给模型"更宽权限"的自适应~~：动态防御只管"更严"，绝不赠与权限。
- ~~红队生成器连真实外部服务/真文件~~：只在离线 mock + 我方靶场跑，明文预算封顶。
- ~~无限扩大载荷库~~：只增"可复现的版本化变体"，不进"一次性话术垃圾"。
